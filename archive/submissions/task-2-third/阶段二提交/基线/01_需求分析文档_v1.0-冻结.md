## 1. 文档目的、术语与需求来源

### 1.1 文档目的

本文规定一个课程级 Web 平台应提供的用户行为、业务规则、输入输出、异常处理、质量属性与验收依据，用于后续用例建模、概要设计、数据库设计、开发和测试。项目定位为“课程作业评测与学习反馈”，而非大型竞赛社区，也不以训练新模型或研制沙箱内核为目标。

正文中“应／不得”表示候选基线中的约束；“建议”表示非强制实现选择。外部资料用于论证技术机制，并不证明本校确有某种教学流程。所有数值规模均为本项目的候选验收条件，不是调查统计或既有系统性能。

### 1.2 术语

| 术语 | 本文定义 |
| --- | --- |
| OJ | Online Judge，按照题目测试数据和资源限制评测程序的系统 |
| 题目版本 | 题面、样例、隐藏测试、比较规则、语言配置及资源限制组成的不可变快照 |

## 2. 背景、问题陈述与目标

### 2.1 背景与问题陈述

本项目拟用于程序设计、数据结构等课程的编程作业场景。候选问题有四类：第一，仅收集代码文件难以统一验证运行结果；第二，只有对错判定不足以指导初学者定位语法、边界和复杂度问题；第三，提交版本、截止时间和重评可能引起成绩争议；第四，学生代码属于不可信输入，直接在业务服务中运行会引入安全与资源风险。

前三类是 A-01/A-03/A-04 所述的业务假设；U-05 确认项目规则，但没有证明问题的普遍性或频率；第四类的隔离设计依据来自官方安全资料，而不是本项目已有事故。[S1][S3][S4]

### 2.2 产品目标与成功条件

| 目标编号 | 产品目标 | 首版可验证的成功条件 |
| --- | --- | --- |
| G-01 | 建立课程作业闭环 | 教师发布作业后，学生能够提交，系统返回评测，教师能够查看和发布成绩 |
| G-02 | 保证结果可解释、可追溯 | 每次结果关联代码、题目版本、语言版本、评测轮次与受理时间 |
| G-03 | 提供受控的学习反馈 | 学生可查看确定性错误说明；符合教学策略时可请求 AI 提示 |
| G-04 | 避免平台故障伤害学生成绩 | SE 不伪装成学生错误；待评测、失败恢复和重评均保留证据 |
| G-05 | 控制课程项目复杂度 | 使用一个业务服务和独立评测适配模块完成，不要求微服务集群或自研沙箱 |

本阶段不承诺“学习效率提高 30%”“AI 准确率 99%”等未经实验的教育效果。模型提示质量按照固定样本和人工量表验收，而不是以产品宣传语替代指标。

## 3. 目标用户、权限与界面

### 3.1 用户角色

学生负责查看作业、编程提交、查看本人结果及学习反馈。教师负责管理本人课程、题目和作业，查看课程学生提交、组织重评并发布成绩。系统管理员负责账号、服务配置、故障处置与审计；管理员不因角色名称自动获得教师的正常教学操作权限。

首版不设助教角色。后续如需要助教，应新增受限课程角色，不复用系统管理员账号。

### 3.2 权限矩阵

| 操作或数据 | 学生 | 任课教师 | 系统管理员 |
| --- | --- | --- | --- |
| 课程和作业 | 仅本人所属课程 | 仅本人管理课程 | 查看元数据、归档维护 |
| 学生源代码和评测记录 | 仅本人 | 仅本人课程内提交 | 默认无业务查看权限 |
| 隐藏测试和参考程序 | 不可访问 | 仅本人课程题目 | 默认不可通过业务界面读取 |
| 成绩和导出 | 仅本人 | 仅本人课程 | 不可直接修改成绩 |
| 账号和评测服务 | 修改本人密码 | 修改本人密码 | 创建／停用账号、配置服务 |
| 运维应急访问 | 无 | 无 | 需关联故障工单和理由，记录审计 |

拥有宿主机或数据库管理权限的运维人员在技术上可能访问底层数据；本文承诺业务层最小权限与运维审计，不虚构对基础设施管理员的绝对隔离。服务端应对每次请求执行身份、角色、课程归属和对象归属检查，而不能只隐藏页面按钮。[S5]

### 3.3 人机界面要求

学生端主要页面为“我的课程、作业详情、题目与编辑器、提交记录、学习反馈”。题目页同时显示语言版本、资源限制、服务器时间、截止时间和提交状态。正式提交与练习提交应使用不同文字标签，不仅依赖颜色区分。

教师端主要页面为“课程成员、题目版本、作业发布、成绩看板、重评”。发布、重评激活、延期和归档等操作应显示影响范围并二次确认。

管理员端主要页面为“账号、服务健康、积压任务、失败任务、审计与备份”。发生评测故障时应显示受影响的提交数量，而非要求管理员从原始日志猜测。

## 4. 系统边界、范围与优先级

### 4.1 首版范围

首版包含账号登录与三类角色、教师维护课程成员、C++17 与 Python 3 的标准库、单线程、单文件代码提交、题目版本与测试数据、作业时间控制、异步评测、结果追溯、确定性学习反馈、受控 AI 提示、成绩统计与发布、重评、故障恢复及审计。

语言的具体编译器／解释器版本应通过实际部署探测后写入冻结清单，并在提交页面展示。任何版本变更均需记录，不把“Python 3”理解为全部 3.x 环境完全等价。未完成两种语言的最小联调不得宣称首版已验收。

### 4.2 中低优先级与范围外

| 范围类别 | 内容 | 取舍理由 |
| --- | --- | --- |
| 中优先级 | CSV 成绩导出、自动错题清单、站内通知 | 有明确用途，但不是完成一次评测的前提 |
| 低优先级 | 按教师标签的规则式练习推荐、移动端成绩查询优化 | 仅作为扩展，不训练推荐模型 |
| 明确范围外 | 公开比赛、排行榜、代码查重、论坛、私信、支付、招聘、视频课程 | 避免从教学评测扩展为综合社区 |
| 明确范围外 | 校园统一身份认证、教务系统成绩自动回写、短信和邮件服务 | 外部接入条件尚未获得 |
| 明确范围外 | 交互题、特殊判题器、浮点容差判题、多文件项目、多进程／多线程程序、联网程序、GPU 任务 | 显著扩大执行与判分复杂度 |
| 明确范围外 | 自研沙箱内核、训练大模型、AI 自动判定抄袭、自动修改正式成绩 | 缺乏必要性或风险过高 |

删除中低优先级功能不得连带删除其安全约束。例如不做 CSV 导出时无需验收导出行为；但只要启用导出，就必须做权限检查和公式注入防护。

### 4.3 外部依赖与候选实现方向

建议采用 Web 前端、单体业务后端、关系数据库、持久任务记录、独立评测适配器和受限模型网关。具体前端框架和后端语言由设计阶段确定，不作为用户需求。

评测后端以可自部署的 Judge0 CE 为候选，利用其代码执行与资源限制接口；多测试点评测、统一输出比较、成绩、课程权限和重评仍由本平台负责，不能把代码执行 API 当作完整 OJ。[S1]

Docker 官方资料表明容器安全依赖命名空间、控制组、权限与配置等多层机制；“使用 Docker”不等于安全验收完成。[S4] Judge0 官方发布记录包含安全修复，部署前需核对选定版本及安全公告，不能因版本号较新就宣称不存在漏洞。[S3]

实际学生代码仅允许在专用 Linux x86-64 评测虚拟机或独立主机运行，不与业务数据库共用不隔离的宿主环境。需要的沙箱内部特权只能存在于该隔离边界内，不得向学生进程暴露宿主控制接口。普通个人电脑可进行业务开发，但不默认其可承受公开不可信代码。

模型服务可选择本地部署或授权 API。首版验收至少接入一个真实模型；模拟服务仅用于故障和接口测试，不能替代 AI 功能成功验收。未获教师允许时，默认关闭作业开放期间的 AI 提示。

**模型依赖冻结门禁（DEP-AI，已确认但尚未配置）。** 在首次真实调用前，需求负责人须登记服务商／模型／可用区域、官方服务条款与隐私说明链接及核对日期、代码留存／训练用途说明、许可或账号使用范围、限额、输入输出 token 单价与币种、单次最大 token、日预算 B_day 和实验总预算 B_total。未填写或未获需求负责人确认时禁止调用收费接口，不以免费额度必然存在为前提。未确定服务商时不填写虚构单价。费用上界按 `(输入token×输入单价＋最大输出token×输出单价)/计价单位` 估算，发送前原子预占；失败、重试及超时可能收费，只有供应商确认无费用才释放对应费用预占；不能因未返回 READY 就把实际成本记零。剩余额度不足返回 AI_BUDGET_EXHAUSTED 并提供固定帮助。

字节限制不是 token 限制，须按选定模型分词器测量。密钥仅保存在服务端，不写入文档、浏览器或日志。用户未同意外发本人代码时不调用外部模型；服务条款不适用时改用符合条件的本地模型或提出范围 CR。作者已确认本阶段暂不采购或调用收费模型；在服务商、条款、隐私、限额、计价、B_day 和 B_total 登记并确认前，禁止收费调用。该门禁仍是后续验收前提，当前没有供应商配置或实际调用。关联 FR-20/22、NFR-05/18/19、ST-16。

## 6. 核心业务规则

### 6.1 时间、身份与版本

**BR-01 权限与归属。** 每次请求均依据服务端身份和课程成员关系授权。学生不可在请求体指定有效的 user_id 替他人提交。跨课程访问不存在授权时返回 404，未登录返回 401，已登录但无相应操作角色返回 403。

**BR-02 截止时间。** 时间以服务器 UTC 毫秒保存，界面默认显示北京时间 UTC+8 并明确标注。正式提交时间区间为 `[open_at, due_at)`：等于开放时刻允许，等于截止时刻拒绝。服务器在受理事务中锁定作业记录后读取数据库当前时刻（非事务开始时刻）作为 accepted_at；事务成功后该时间生效。排队和评测结束时间不影响正式提交资格。

**BR-03 截止后与延期。** 截止后新提交只能为练习提交，不计分。教师可延长截止时间并填写理由，不得将其提前至已有正式提交之前；延长后已存在的练习提交仍不追认成绩。用户可在重新开放期间重新正式提交。服务器时钟漂移超过 1 秒时告警，超过 5 秒时暂停新正式提交并显示故障，不使用客户端时间替代。

**BR-04 题目版本。** 发布后被作业引用的题面、隐藏测试、比较规则、分值和语言资源配置不可原位修改。纠错须生成新版本并按 BR-09 组织统一重评。语言运行环境变化同样进入版本记录；同一成绩批次不得混用未经声明的运行环境。

### 6.2 评测、输出比较与计分

**BR-05 题型和比较规则。** 首版仅支持标准输入／标准输出的非交互文本题。比较过程固定为：将 CRLF 转为 LF；按 ASCII 空白字符集合 `空格、\t、\n、\r、\v、\f` 切分；比较 token 数量及每个 token 的字节内容。忽略这些分隔空白的数量，不忽略大小写，不做数值转换或 Unicode 归一化。因此 `1 2` 与 `1\n2` 相同，`1.0` 与 `1` 不同，`01` 与 `1` 不同。参考答案采用 UTF-8；样例与隐藏测试使用同一比较规则。不将适配器默认比较规则视为本规则。

**BR-06 判定流程。** 编译失败返回 CE；解释型语言由后端实际阶段决定，Python 语法错误以冻结后端的实际失败阶段为准：编译阶段失败映射 CE，运行阶段失败映射 RE；DD-07.engine_meta 留存阶段、后端状态和映射版本，不凭错误文字猜阶段。测试点按编号递增串行处理，首个非 AC 即停止。正常退出且输出匹配才为 AC；正常退出且不匹配为 WA；CPU 或执行墙钟超限为 TLE；程序异常或确证的内存／输出限制触发为 RE 并记录资源原因；执行器、传输、题目文件损坏等平台故障为 SE。先检查基础设施错误，再检查运行异常，最后比较输出。

**BR-07 资源约束。** 每题 1—10 个隐藏测试。每个测试点默认内存上限 256 MiB、单个输出文件上限 1 MiB、单任务工作目录配额 32 MiB；C++17 CPU 上限 2 秒／墙钟 5 秒，Python 3 CPU 上限 4 秒／墙钟 10 秒。编译阶段另限墙钟 20 秒、内存 512 MiB。所有限制由服务端配置，学生不可覆盖。内存上限覆盖程序进程集合；编译和执行均禁网；编译阶段进程／线程总数候选上限 30，学生运行阶段进程／线程总数上限 1（含主执行实体），须通过部署层实际计数验证；后端参数是否含主进程不得仅按名称推定，均须分别自测并锁定，不允许学生程序主动创建额外进程或线程。单轮处理最多 360 秒；超过属于执行协调异常 SE，不假装为学生程序 TLE。后端无法满足必要限制时不得开放正式提交。

**BR-08 计分。** 作业题目分值均为正整数，总和为 100；每题所有隐藏测试 AC 才获得该题全部分值，否则该次得分为 0。学生每题取“有效正式提交中当前生效评测结果”的最高得分，作业成绩为各题得分之和。无正式提交为 0；尚未完成或只有 SE 的提交标注待处理，不虚构已判失败。存在任何尚未终结或仍为 SE 的正式提交时，或 BR-17 事件尚未裁决／补偿未生效时，教师不得发布最终成绩。首版不做测试点部分分。

例：三题分别 30、30、40 分；学生第一题有 WA 和 AC，第二题为 WA，第三题仅有 SE，则当前已确认得分 30，成绩状态为待处理，而不是已发布的 30 分。第三题成功重试为 AC 后可发布 70 分。

**BR-09 重评一致性。** 正式重评只允许在作业已截止、原正式提交均已终结（可含SE）且无未裁决补偿事件后发起；仍在运行的旧任务先依BR-11完成或收敛，以固定范围。原SE可以通过新版本统一重评修复，但新批次激活仍要求全部非SE。活动重评批次期间不得延期重新开放；确需补偿时先取消未激活批次并保留其历史结果，再延期，当前已生效版本不回滚。由作业锁与revision保证延期／重评发起互斥，避免新正式提交漏出重评范围。新版本影响某作业题目时，重评范围包含该题所有正式提交，而非只挑选某个学生或原先 AC 的提交。旧结果只读保留，标记待核查；新批次全部取得非 SE 终态后，教师确认激活，统一切换有效版本并重算成绩。新评测可以提高或降低成绩，不能继续保留已失效版本的最高分。失败批次不可部分激活；此前已发布成绩显示“重评中”，完成后产生新成绩版本。练习提交保留原版本，不自动纳入正式成绩重评。

### 6.3 可靠性与 AI 教学边界

**BR-10 幂等与重复执行。** 幂等键由客户端为一次用户提交生成 UUID，服务端按“用户＋幂等键”至少保留 24 小时。相同键与内容返回原提交；相同键但内容不同返回 409。先验证身份与既有键，再判断新提交资格，因此截止后重发已成功受理的同一请求仍可找回原提交。平台允许底层至少一次投递，但同一有效评测轮次最多计入一次成绩；过期轮次结果不得覆盖新结果。

**BR-11 故障与重试。** 已受理任务由持久记录恢复，不依赖浏览器或仅内存队列。基础设施故障自动重试最多 1 次，仍失败记 SE 并允许管理员填写原因后手动重试；学生 WA/CE/TLE/RE 不自动重试。自动流程中自受理起 15 分钟仍无终态的提交应转为 SE 并释放资源。人工重试开启新轮次并重新计时，不增加学生正式提交次数。数据库不可写时返回失败，不宣称受理成功。

**BR-12 隐藏数据保密。** 学生可见公开样例、本人代码、经清理的编译诊断、每个已执行测试点的判定和资源统计。隐藏测试的输入、期望输出，以及执行学生代码得到的 stdout/stderr 均不得返回给学生或 AI，因为程序可将隐藏输入复制到输出。学生页面可以显示“第 3 个测试点 WA”，但不得显示其原始数据或直接可下载地址。

**BR-13 AI 权限和内容。** 作业开放期间默认禁用 AI；教师可在发布前选择“允许提示”，开放后只允许关闭，不允许临时放宽。截止后允许学习提示。权限按canonical_problem_id及该学生所属全部课程的相关开放作业联合检查：同题任一版本或已标记衍生题仍被禁用AI的开放作业引用时，不得经旧版本、跨课程或练习入口绕过；未标记的语义相似题不能保证自动识别，教师须维护同族关联。服务端判定策略，模型不能自行授权。

AI 仅接收公开题面、公开样例、本人代码、已脱敏编译诊断与粗粒度判定；不接收隐藏数据、参考程序、其他学生代码或身份信息。学生首次向外部模型发送代码前须主动确认数据范围；拒绝不影响评测。模型无执行工具、数据库写入权或修改分数权。[S6]

**BR-14 AI 输出及额度。** 提示只包含错误类别、定位线索、待检查边界和下一步学习建议；不以完整可运行解答为产品输出目标。不能保证模型从不出错，必须显示“AI 建议，需自行验证”。每账号每天最多 20 次 READY 提示，按请求被接纳时所属北京时间自然日记账。仅当该日 READY 数＋未释放预占数小于 20 才允许新请求；达到 20 后的新请求在模型调用前返回 429/AI_DAILY_QUOTA，不存在“第 21 次成功”。跨日执行仍记入原接纳日；新日期使用独立计数。重复 request_key 返回原结果，不再扣次数；失败释放预占，不撤销外部供应商已经产生的实际费用。每人最多 1 个进行中请求。全平台模型并发上限 2，等待位 10，等待超过 10 秒拒绝，请求执行超过 20 秒中止。AI 不可用时仍展示确定性帮助，不影响提交、评测和成绩。

**BR-15 发布与留存。** 归档课程仅可查看和导出已有数据，不可新增提交或重评。课程归档满 180 天后可由管理员经教师确认执行逻辑清理；正式清理后 30 天内删除可恢复副本，备份按既定 30 天轮换淘汰。正在申诉或重评的数据暂停清理。此期限是课程原型的候选业务规则，不是对任何法规或学校制度的断言。

**BR-16 并发与冲突。** 作业编辑、延期、归档、重评激活采用版本号冲突检测；过期版本写入返回 409，要求重新读取，不以最后写入静默覆盖。提交事务与作业状态变化应在同一一致性边界内判断，禁止“检查时开放，持久化时已关闭但无记录依据”的竞态。


**BR-17 截止高峰与公平补偿（已确认项目规则，待系统实测）。** 任一已发布且未归档作业处于截止前10分钟至截止的窗口时，整个评测服务停止派发新的重评任务；已经执行的任务不强杀。所有正式请求仍按 NFR-03 校验，不取消个人 5 秒间隔和 3 个未终结上限。429 应区分 STUDENT_INTERVAL、STUDENT_PENDING_LIMIT，503 应区分 GLOBAL_CAPACITY、JUDGE_UNAVAILABLE、PERSISTENCE_UNAVAILABLE；合法请求因平台容量被拒绝不能被隐藏为学生错误。

对截止前 10 分钟内发生的容量拒绝、服务／持久化故障、严重时钟错误，以及平台积压导致正常学生持续占满 3 个未终结名额，登记故障事件并标记相关作业 fairness_review=PENDING；只违反已公布的 5 秒间隔、非法代码请求或个人网络中断，不自动归因平台。事件记录开始／恢复时间、request_id、原因码、影响作业和拒绝数，不记录源码。完全断电无法留请求日志时，管理员可凭监控或部署故障证据补记“证据不完整”的事件，教师人工裁决；不能要求学生出示平台根本无法生成的回执才受理申诉。

任课教师应在恢复后 1 个工作日内完成裁决；逾期告警管理员，系统不得自动记为已解决。确认影响正常提交机会时，必须对受影响作业的全部学生统一延期并填写故障编号，候选公式为 `new_due = max(old_due, recovered_at, approved_at) + max(故障持续时长, 10分钟)`；故障持续时长取与该作业开放区间相交的连续故障区间长度，多段相邻故障合并登记。界面向全班显示新截止及理由，不依赖中优先级通知功能。重复故障可再次裁决。若判定未影响正常提交，教师写明证据和不延期理由后解除标记。

补偿不倒填 accepted_at、不追认旧练习提交、不直接加分；在新开放区间重新提交才计正式成绩。已受理任务始终保留原正式资格。事件未裁决／补偿未生效前，禁止相关作业最终成绩发布、相关课程归档和争议数据清理。教师只可延长，不可通过补偿提前原截止；延期后已发布成绩回到 PROVISIONAL，新截止后重新发布新成绩版本，旧快照只读。该规则已由作者确认作为本项目规则，不冒充既有学校制度；平台影响和补偿效果仍需 ST-13/ST-14 实测。

## 7. 状态模型

### 7.1 作业状态

`DRAFT → SCHEDULED → OPEN → CLOSED → ARCHIVED`。

DRAFT 仅教师可见；SCHEDULED 为已发布但未到开放时间；OPEN 允许正式提交；CLOSED 仅允许不计分练习；ARCHIVED 只读。有效状态由服务器时间和归档标志共同计算，不依赖后台定时器恰好在截止秒执行。教师延期可以使 CLOSED 回到 OPEN，但不得追认旧练习提交。

### 7.2 提交和评测状态

提交处理状态为 `QUEUED → JUDGING → FINISHED`。等待或执行失败可进入 `RETRY_WAIT → QUEUED`；无法恢复则进入 `FINISHED` 且 verdict 为 SE。正式性、处理状态、评测判定是三个独立字段，不将“正式／练习”和“AC／WA”混成一套枚举。

重评创建新的 generation 和 attempt_id，不改变原 submission_id、source_code 与 accepted_at。旧轮次迟到结果可以作为历史保存，但不得更新当前轮次。FINISHED 不被轮询或重复消息恢复成 JUDGING。

## 9. 数据、输入输出与接口约束

### 9.1 数据字典

所有业务接口使用 UTF-8 JSON；ID 为不可复用的字符串；时间采用带时区的 ISO 8601 格式。代码和输出大小按 UTF-8 编码后的字节计算，不能以字符数冒充字节数。KiB=1024 字节，MiB=1024 KiB；UI 中必须写明单位。

| 编号／对象 | 主要字段 | 格式、约束与可见性 |
| --- | --- | --- |
| DD-01 账号 | user_id、login_name、display_name、role、status | login_name 为 3—32 位 ASCII 字母数字下划线且唯一；display_name 为 1—40 个 Unicode 字符；密码 12—128 个字符，不截断、不存明文；登录名不是学号强绑定 |
| DD-02 课程与成员 | course_id、teacher_id、title、member_id、member_status | 课程名 1—100 字符；成员组合唯一；课程归属由服务端设置；演示使用虚构学生标识 |
| DD-03 题目版本 | problem_id、version_id、title、statement、samples、tags、profile | 标题 1—100 字符；题面不超过 32 KiB；1—3 组公开样例，每份输入／输出不超过 4 KiB；标签最多 5 个，每个 1—20 字符；canonical_problem_id为必填的题目家族标识（AI策略与同族推荐过滤共用）；practice_released默认为false，推荐启用时由教师明确发布 |
| DD-04 隐藏测试 | testcase_id、order、input_blob、answer_blob、checksum | 1—10 组；编号连续；每个文件不超过 64 KiB；两文件配对；仅教师和评测服务可访问；保存校验值 |
| DD-05 作业 | assignment_id、course_id、items、open_at、due_at、ai_policy、revision | 1—20 道已发布题目，各题分值为正整数且总和 100；同题不能重复；open_at < due_at；ai_policy 为 DISABLED/HINT；fairness_review 为 NONE/PENDING/RESOLVED，关联故障记录 |
| DD-06 提交 | submission_id、user_id、assignment_id、version_id、language_key、code、accepted_at、mode | 单文件代码 1—64 KiB且不允许全空白；language_key 必须在版本白名单；请求头 X-Submission-Intent 必填 FORMAL/PRACTICE；mode 仍由服务端校验时间后计算，意图不合法返回409，不静默把正式请求变为练习；提交后源码不可修改 |
| DD-07 评测轮次 | attempt_id、generation、state、verdict、case_results、time_ms、memory_bytes、engine_meta | verdict 非终态时为 null；time_ms 为已执行测试点 CPU 时间总和，memory_bytes 为峰值；指标缺失为 null 而非 0；engine_meta 内部记录 backend_version、language_version、phase(COMPILE/RUN/INFRA/UNKNOWN)、raw_status、mapping_version、resource_reason；未知阶段不得编造 |
| DD-08 AI 提示 | hint_id、submission_id、model_version、template_version、status、hint_sections、feedback | 用户附加问题 0—500 字符；AI 上下文总代码及公开资料上限 24 KiB，超限拒绝并仍提供固定帮助；输出最多 2000 个 Unicode 码点或 8 KiB UTF-8 字节，以先触达者为准；避免“中文等价字符”无法计量 |
| DD-09 成绩快照 | grade_version、student_id、item_scores、total、state、published_at | total 为 0—100 整数；state 为 PROVISIONAL/PENDING/PUBLISHED/REJUDGING；存在待处理项时不得伪装成最终分 |
| DD-11 公平补偿事件 | incident_id、assignment_ids、started_at、recovered_at、reason_code、rejected_count、evidence_refs、decision、approved_at、old_due、new_due | 时间带时区；decision 为 PENDING/EXTEND/NO_IMPACT；批准人必须是任课教师；缺少恢复时间不得完成延期裁决；证据不完整须显式记录；审计保留至少180天且争议中暂停清理 |
| DD-10 审计 | event_id、actor_id、action、object_id、before_after_digest、reason、timestamp、request_id | 敏感操作理由 10—500 字符；日志不含密码、令牌、隐藏测试正文或整段源码；保留至少 180 天 |

题面和 AI 文本不得执行原始 HTML、脚本、内联事件或自动加载外部图片。代码编辑器内容只作为文本存储和展示。教学题目与测试应由教师自编或确认具有使用授权，不以“课程作业”代替版权来源说明。

### 9.2 核心接口契约

下表限定可观察行为；路径是候选契约，可在设计阶段经变更记录调整。列表分页默认 20 条、最大 100 条，排序必须稳定。

| 接口 | 主要输入 | 成功输出与失败行为 |
| --- | --- | --- |
| IF-01 POST /api/v1/submissions | assignment_id、problem_id、language_key、code；请求头 Idempotency-Key、X-Submission-Intent | 202：submission_id、accepted_at、mode、state；幂等重放返回原记录，不新建；400/401/403/404/409/413/429/503 按错误原因返回 |
| IF-02 GET /api/v1/submissions/{id} | 登录会话、路径 ID | 200：DD-06/DD-07 的授权视图；学生响应剔除隐藏输入输出、执行 stdout/stderr 和内部凭据 |
| IF-03 POST /api/v1/ai-hints | submission_id、可选 question、data_sharing_consent、request_key | 202：hint_id、PENDING；随后查询获得 READY/FAILED/BLOCKED；相同请求键不重复扣费；策略拒绝返回 403 |
| IF-04 POST /api/v1/assignments/{id}/rejudge | new_version_id、reason、expected_revision | 202：batch_id、影响的提交数；教师预览确认后发起；作业仍开放、原提交待处理、活动批次或版本冲突返回409 |
| IF-05 POST /api/v1/rejudge-batches/{id}/activate | expected_revision、reason | 200：新成绩版本；存在未完成／SE 或批次过期时返回 409，不部分生效 |
| IF-06 GET /api/v1/assignments/{id}/grades.csv | grade_version、过滤条件 | 中优先级：UTF-8 CSV，固定列及状态；越权失败；导出与该版本快照一致 |
| IF-07 业务服务→评测适配器 | 代码、语言配置、单个测试输入、资源配置、attempt_id | 返回内部任务 token，之后查询结果；后端与公网学生端隔离；传输失败保留本地任务，不重复计分 |
| IF-09 POST /api/v1/assignments/{id}/fairness-decisions | incident_id、decision、reason、expected_revision | 教师裁决；EXTEND 根据 BR-17 计算 new_due 并原子更新事件及作业；PENDING 不能发布成绩；过期版本409；成功200返回新revision、截止与状态；只读事件查询随作业详情提供授权摘要 |
| IF-08 业务服务→模型网关 | 公开题面、本人代码、粗粒度判定、受控模板 | 返回结构化提示；解析失败或超时按 BR-14 降级；不允许模型回调执行工具或更改成绩 |

统一错误结构包含 `code、message、request_id、retryable`。429/503 在可重试时附 Retry-After；message 面向用户，不包含服务堆栈、数据库结构或绝对内部路径。未识别字段默认拒绝，不允许通过额外字段覆盖资源限制。

提交请求示例：

```json
{
  "assignment_id": "asg_001",
  "problem_id": "prob_001",
  "language_key": "cpp17_frozen_profile_1",
  "code": "#include <iostream>\nint main(){std::cout << 3;}"
}
```

受理响应示例（示例数据，不是实测返回）：

```json
{
  "submission_id": "sub_001",
  "accepted_at": "2026-10-08T11:59:59.900Z",
  "mode": "FORMAL",
  "state": "QUEUED"
}
```

这里 language_key 是本平台的语言配置标识，不直接写死某个第三方 language_id。适配器须探测实际环境、记录映射并通过最小用例核对；若环境改变导致映射失效，应停止受理相应语言，而不是悄悄换用另一版本。[S1]

### 9.3 核心数据一致性

提交、代码快照与待投递任务应在同一持久化事务中建立；队列可以重复投递但不能成为唯一账本。成绩依赖当前生效评测轮次和作业题目分值，不能仅把最高分累加进某个字段而丢失来源。重评切换、课程归档、作业延期均要记录操作者、理由、旧值、新值和数据版本。

平台禁止任意修改最终分数。题目有误通过版本纠错与统一重评处理；教学加分、人工酌情评分属于范围外，不在本系统中暗设后门。

## 10. 非功能需求与验证方法

### 10.1 验收环境与负载口径

**E-01 候选环境。** 业务端 4 vCPU、8 GiB 内存、100 GiB SSD；独立评测虚拟机 4 vCPU、8 GiB 内存、60 GiB SSD；独立备份空间至少 250 GiB。评测并行槽位设为 4。操作系统、CPU 型号、虚拟化方式、编译器版本、模型版本和镜像摘要均写入测试报告。两台虚拟机可以位于同一足额物理机，但不得把资源超售情况下的结果称为等效测试。此配置是候选预算，未证明用户已具备。

**W-01 业务负载。** 300 个学生账号、10 个教师账号、10 门课程、1000 个题目版本、100000 条历史提交作为合成背景数据。50 个已登录虚拟用户，每人每 3 秒发起一个请求，按 40% 作业列表、30% 题面、30% 本人提交详情混合；预热 2 分钟后持续 30 分钟。性能指标以客户端完整请求耗时统计；压测客户端与服务端网络 RTT 应小于 10 ms，版本与缓存冷热状态固定。

**W-02 评测负载。** 在 W-01 背景下，每 10 秒提交 1 份正确短程序，共 180 份，两种语言各占一半。题目为整数求和、数组最大值、数组求和，每题 3 个测试点，每点预热 CPU 用时不超过 100 ms、输出不超过 1 KiB。另用 20 个不同学生账号做“20 份提交在 10 秒内到达”的突发实验。所有失败、超时和被拒绝请求均单独报告，不得通过只统计成功样本掩盖容量问题。

**W-03 AI 负载。** 选定的真实模型、固定模板、相同 30 份反馈评估输入；最多 2 个并发，固定输入预算。另以模拟服务注入超时、限流、无效 JSON 和断网。模拟结果只证明降级逻辑，不证明真实模型质量。

**容量推算说明。** 若预实验测得一份短提交平均占用槽位 10 秒，则 4 槽位理论吞吐为 4/10=0.4 份／秒；W-02 的到达率为 0.1 份／秒，约为该假定容量的 25%。这仅说明候选指标在数量级上有余量，不是吞吐保证。真实占用时间必须测量；若明显更长，应降低负载目标、增加资源或改进实现，并记录变更。

### 10.3 截止前 10 分钟高峰容量与迟交公平性

用 W-02 的“逻辑提交／秒”计到达率，不能把一个含 3 个测试点的提交只算成一次后端 API 调用成本。设槽位数 c=4，完整提交平均占槽 s 秒（含编译、各测试点和协调开销），估计吞吐 μ=c/s；仅为容量推算，不能代替 P95 实测。多测试点可重复编译时必须把重复成本计入 s。

| 场景（均为假设） | 到达量／到达率 | s=10秒、空队列时的推算 | 能否据此承诺 |
| --- | --- | --- | --- |
| W-02 常态 | 180份/1800秒=0.1份/秒 | μ=0.4；负载率25% | 只说明平均余量，60秒P95仍需实测 |
| W-02 突发 | 20份/10秒=2份/秒 | 理想占槽工作量50秒 | 原120秒门槛仅对该短程序集合成立 |
| 单课100人最后10分钟各1次 | 100/600≈0.167份/秒 | 约250槽位折算秒，可在600秒内排空 | 平均可消化，不证明最后一秒突发也公平 |
| 全平台300人同一截止各1次 | 300/600=0.5份/秒 | 10分钟仅约240份；均匀到达至少积压60份 | 已超过稳态吞吐；集中到达还会撞100上限 |
| 300人各3次 | 900/600=1.5份/秒 | 600秒内缺口约660份，远超100缓存 | 5秒个人间隔不能解决总量不足 |
| 长任务极端 | 一轮最多360秒；4槽 | 吞吐仅约0.011份/秒；100份需约9000秒 | 15分钟收敛会产生SE，不能当成正常容量 |

以上尚未扣除重评、已有积压和故障；4:1 调度在两队列持续非空、同等成本时还会分走约20%的派发机会。保护窗口只暂停新重评，已执行长任务仍会占槽，因此正式开放前要验证任务组合并安排课程截止错峰，不能静默缩短学生资源限制。3个未终结名额与5秒间隔都是限滥用措施，不是“准备好的代码保证受理”。在截止前最后1秒到达的新请求也可能因事务锁等待跨过截止；界面提前提示，不能将客户端点击时间当作证据。

**W-04 新增高峰验证。** 使用 W-01 背景和 W-02 固定代码，分别执行：(a) 空队列100个不同账号10秒内各提交一次；目标全部持久受理且300秒内取得非SE终态；(b) 300个账号10秒内各提交一次，不承诺全部接纳，验证最多100个未终结、每个请求均有明确结果或可查询幂等结果，超量拒绝被准确记录；(c) 同一学生已有3个长时间排队任务、距截止2秒再次请求，确认拒绝原因与平台积压事件；(d) 截止前服务不可用并恢复，走统一补偿。受理P95≤2秒、限流响应≤2秒；报告成功／拒绝／超时分母、槽位占用均值及分位数，不把(b)的预期容量拒绝计作W-01业务故障率，也不隐去。

W-04(a)指标是新增候选目标，若不满足须调整资源、错峰计划或经CR改容量基线；不能凭推算宣称可行性已验证。(b)(c)(d)必须通过ST-13/ST-14的证据与补偿检查。扩大队列只能减少即时拒绝，不能提升吞吐，也不能绕过15分钟SE上限。

### 10.4 AI 提示质量二值量表与评审程序

### 13.2 优先级依据

高优先级并不等于仅选择高频功能。登录、浏览、提交属于高频核心；隔离、重评、恢复和留存虽然触发频率较低，但涉及数据安全、成绩公平或已受理数据，不可因此降为可选。CSV、错题和通知有实际用途但可暂时由界面查询或人工提醒替代，因此列为中；推荐与移动查看是体验优化，因此列为低。

本次共定义 29 项功能需求，其中高 25 项、中 3 项、低 1 项；24 项非功能需求，其中高 22 项、中 1 项、低 1 项。高优先级 AI 功能限定为受控提示，而不是完整问答代理；这使“智能”有可演示内容，同时避免研究型算法扩张。

### 13.3 变更控制

需求编号发布后不得重用。变更记录格式为 `CR-编号、提出者、日期、原需求、修改内容、理由、影响的 BR/FR/NFR/DD/AC/NT、批准人、目标版本`。任何人不得只修改性能数值而不更新负载、硬件、验收步骤和追踪关系。

示例（尚未提出的模板，不算真实变更）：若教师要求“截止后 24 小时可补交并按 80% 计分”，需同步修改 BR-02/BR-03/BR-08、DD-06/DD-09、FR-09/FR-11/FR-17/FR-18 和 ST-01/ST-07；不能只在页面增加“补交”按钮。

v0.9 为首次提交，v1.0-rc1 为历史候选稿；本版 v1.0 已记录作者逐项确认和整稿审阅。真实资源、独立评审和后续测试发现问题时，形成 v1.1 或 CR，并同步更新受影响的规则、需求、设计和测试。AI 对方案的编辑建议不自动成为学生批准的决定。
