# 部署与运维

本项目按双人课程大作业规模交付：一个可重建的课程环境、必要管理页和可执行脚本。下表表示用途，可复用同一套Compose/profile并隔离数据库和数据；不要求长期维护三套独立集群。保留执行隔离、数据恢复与验收目标，不建设高可用、多地域容灾、自动扩缩容、值班制度或独立监控平台。

## 1. 环境

| 环境 | 用途 | 条件 |
| --- | --- | --- |
| 本地开发 | 页面、业务、契约与测试 | Windows/WSL或Linux；API/Worker/PostgreSQL可共用开发宿主；执行器替身不得接受真实不可信代码 |
| 集成 | 双人联调、故障及迁移 | 独立数据库、虚构数据；真实评测在专用Linux VM；模型默认关闭，验证后启用 |
| 验收/发布 | 全流程、容量、隔离与恢复 | 按质量文档登记足额资源、HTTPS、独立备份、冻结镜像/语言/模型配置 |

同一VM内再放容器不等于业务和评测分离。评测VM只开放鉴权管理入口给业务Worker，学生程序禁网。数据库只允许API、Worker和维护账号访问；提示Worker不持有评测区控制权限。

## 2. 配置与秘密

P0提供 `.env.example` 和结构校验，实际值进入未跟踪 `.env` 或部署秘密存储。配置至少包括数据库连接、会话/CSRF密钥引用、域名、评测入口/凭据引用、语言profile摘要、槽数、超时、模型配置ID/密钥引用、预算、备份目标和日志等级。配置缺失或不合法启动失败，不能默默采用不安全默认值。

密钥不进入前端bundle、Git、普通日志或测试截图；账号密码、Cookie、源码与隐藏正文脱敏。生产禁止DEBUG、通配凭据CORS和公共数据库端口。业务账号非数据库超级用户；迁移、备份、只读监测各有独立最小权限。

依赖锁、Python/Node版本、数据库大版本、系统和镜像digest写入部署清单。语言profile记录编译器/解释器版本、实际资源单位及映射版本。模型使用官方接口，启用前核实账号、区域、数据留存/训练用途、价格、预算、token计数、返回schema和质量回归；不把旧文档展示名当当前不可变模型版本。

## 3. 启动与发布顺序

1. 从指定commit和锁文件构建镜像；检查产物摘要与验收版本一致。
2. 验证备份可读、环境配置、数据库权限和维护窗口。
3. 暂停新写入，排空或安全保留持久任务；按迁移计划升级数据库。
4. 启动API与Worker，检查readiness、迁移版本、时钟、磁盘、队列恢复。
5. 验证隔离执行器健康/profile；执行虚构账号的两语言冒烟、成绩对账和授权检查。
6. 开放业务流量，观察错误率、队列、SE、容量和预算；出现阻断问题停止新受理并回滚。

数据库变更采用向前兼容扩展。代码回滚只能选择兼容当前schema的版本；不兼容时进入维护并按验证过的备份恢复流程处理，明确RPO内可能缺失的写入，不以 `alembic downgrade` 盲目删除生产数据。

## 4. 健康检查与故障处理

| 指标/条件 | 响应 |
| --- | --- |
| API响应与业务失败率 | 按W-01目标告警，区分预期拒绝与系统故障 |
| 队列等待、逻辑容量、槽位状态、SE比例 | 显示影响任务数，停止异常节点新派发，恢复持久任务 |
| Worker失联15秒 | 检查租约、监督清理，未确认退出隔离槽位；不能直接重跑 |
| 故障与恢复 | 60秒内展示故障，恢复后60秒内开始处理；实际检测/展示/落库时间分别记录 |
| 时钟偏差>1秒/>5秒 | 告警/停止新正式提交；保留查询、恢复与已有受理事实 |
| 磁盘≥80%/≥90% | 告警/停止新增代码和测试写入；不删除已受理数据；留审计写入预留空间 |
| 模型预算、超时、异常返回 | 停止新调用，展示固定帮助；未知费用继续预占，对账后结算 |

监测由健康接口、结构化日志和管理页状态实现；告警先使用管理员可见提示和运行日志，不引入额外监控产品。B交付脚本/页面，另一成员按手册验证。

故障恢复顺序：限制新写入/派发→保护已受理账本→确认执行器物理退出→恢复数据库和Worker→补记故障与超时→对账容量/结果/成绩/预算→恢复受理→教师处理公平裁决。数据库不可写时由宿主轻量健康检查脚本保存不含代码的故障摘要，恢复后补录并标记证据完整程度。

## 5. 备份、恢复与清理

每日备份业务数据、源码、测试文件、版本及非秘密配置；保留30天独立恢复窗口，备份加密并限制读取。密钥通过独立秘密恢复流程管理，不能随明文数据库导出公开。P3由另一成员在空环境完成一次完整恢复，记录RPO≤24小时/RTO≤2小时及100个样本校验；备份格式/恢复链变化、影响旧备份兼容性的持久化变更或演练失败修复后重跑；普通兼容迁移执行升级、对账和脚本自检。

清理只通过服务端预览→教师确认→管理员执行：归档满180天、无申诉/活动批次/未决公平事件、引用允许且清单未变才执行。审计至少180天；逻辑清理后30天内淘汰可恢复副本。任何hold优先，不能仅依据文件修改时间直接删数据库相关文件。

## 6. 运行交付清单

发布时必须具备安装/升级/回滚命令、环境变量说明、管理员初始化步骤、题目导入与自检步骤、两语言验证脚本、故障处理、备份恢复和清理操作说明。所有命令由另一成员在干净环境复现。P0建立命令和Compose配置，后续阶段随实际实现更新；当前目录说明不是可运行部署。
