# 界面与交互规范

## 1. 设计方向

参考 [Notion](https://www.notion.com/) 的文档与工作区秩序，以及 [Claude](https://claude.com/) 的温暖、克制气质。以下为 Astra 自身设计标准，不复制品牌标识、插画或专有字体。界面重点是题目、代码和反馈；首页直接进入工作台，不设置营销落地页。

## 2. 视觉基础

| 项目 | 规范 |
| --- | --- |
| 背景 | 页面暖白 `#F7F6F2`，内容面 `#FFFFFF`，侧栏 `#F0EFEA` |
| 文字 | 主文字 `#242320`，次文字 `#66635C`，禁用文字仅用于不可操作项 |
| 边界 | `#DCD9D1`，1px；用留白、分隔线和层级组织内容，减少卡片套卡片 |
| 强调 | 主操作深色 `#302F2C`；品牌陶土 `#9C4B32`，只用于少量焦点和选中强调 |
| 状态 | 成功 `#256644`、警告 `#8A5714`、错误 `#AA3434`、平台故障独立图标与文字；不可仅以颜色区分 |
| 字体 | 正文 Noto Sans SC/思源黑体，本地回退 PingFang SC/Microsoft YaHei；少量标题 Noto Serif SC/思源宋体；代码 JetBrains Mono，均采用可再分发授权版本 |
| 字号 | 正文 14—16px，辅助≥12px，页面标题28—32px；行高正文1.6、代码1.5 |
| 间距 | 4/8/12/16/24/32/48px；页面边距桌面32px、窄屏16px |
| 圆角 | 输入和按钮6px，容器8px；避免大面积胶囊和夸张阴影 |
| 动效 | 120—180ms 的 opacity/颜色过渡；不让按钮命中区随动效位移；减少动态偏好时关闭非必要动画 |

统一以 CSS variables 落地，A 维护 design tokens，B 不在管理页另建配色。正常文本对比度至少4.5:1，较大文字和必要图形至少3:1；上线前以实际相邻颜色检查，不以色值表替代验证。字体自托管或使用系统回退，不从第三方字体服务自动发送用户访问信息。

## 3. 导航与页面

桌面使用 232px 左侧导航、56px 顶部路径与账户区；内容最大宽度1280px，编辑器和成绩大表可扩展。主要操作位于标题同行右侧；每屏只保留一个最高强调的主操作。登录后根据角色进入对应工作区，不在页面上常驻技术诊断或开发说明。

| 页面/路由 | 主要信息 | 操作与状态 |
| --- | --- | --- |
| /login | 产品名、账号密码、登录反馈 | 错误不泄露账号存在；改密要求有独立流程 |
| /courses | 我的课程列表、最近截止 | 按时间排序，学生/教师入口一致但权限不同 |
| /courses/:id | 作业、课程信息；教师成员页签 | 未开放仅元数据；截止、延期公告明确 |
| /assignments/:id | 题目、分值、开放/截止、本人进度或班级统计 | 正式/练习入口和待裁决故障横幅 |
| /assignments/:id/problems/:problemId | 左题目右代码，下方结果抽屉 | 题面/样例、语言环境、资源限制；提交与提示分开 |
| /submissions/:id | 代码快照、判定、逐点摘要、轮次、固定帮助 | 待处理/SE 不伪装为失败；显示当前有效版本 |
| /learning | 错题、推荐、提示历史 | 正式/练习分组，空候选直接提示 |
| /practice-problems/:id | 推荐题目的固定公开版本 | 只读题面/样例；无独立提交按钮；权限失效显示不可用 |
| /teacher/problems | 题目列表、草稿、版本 | 版本发布与自检进度，隐藏测试只在教师维护区 |
| /teacher/assignments/:id/edit | 选题、分值、时间、提示策略 | 分值总计即时校验；已发布内容转只读 |
| /teacher/assignments/:id/grades | 班级表、待处理、版本、重评差异 | 统一发布/导出；不能手填分数覆盖 |
| /teacher/rejudge/:id | 全范围、进度、升降分差异、失败原因 | 激活前确认影响范围；失败成员阻止激活 |
| /teacher/feedback | 固定帮助与模板草稿、预览、版本历史 | 发布不覆写历史，显式区分草稿和生效版 |
| /admin | 服务、队列、磁盘、时钟、预算 | 故障影响数量、重试入口，默认无学生代码 |
| /admin/users | 账号、状态、重置流程 | 理由和确认，不展示密码 |
| /admin/audit | 操作者、事件、对象、时间、请求编号 | 过滤只读；应急访问可追溯 |
| /notifications | 事件、课程、时间、已读 | 跳转后仍校验对象权限 |

页面责任：A负责登录、课程、作业/编辑器、题目维护和learning；B负责提交详情/历史、学生/教师成绩、重评、全部admin及通知。B还提供编辑器结果抽屉和公平公告组件；A只负责在教学页面接入。基础组件/设计令牌由A维护，双方分别完成自己页面的状态、联调、可访问性与回归。

管理页采用公共表格、详情及确认弹窗，覆盖必要动作即可，不追加独立监控大屏或复杂运维工作台。

## 4. 编程工作区

1366×768 下题面占42%、代码占58%，支持拖动分隔线并保留本机设置。代码区顶部显示语言版本，底部固定操作条显示保存状态、正式/练习标签、提交按钮；反馈抽屉不能遮住主要按钮。小于1024px改为题目/代码/结果页签；移动端优先只读。

草稿按账号、作业、题目、语言分区保存在 IndexedDB，500ms防抖，显示本地保存时间；退出账号清除该账号草稿并提示先导出，避免共用设备泄漏。会话失效时保留当前内存草稿并允许复制；重登相同账号才恢复该账号草稿，切换账号不能展示上一人的代码。

一次提交生成一个幂等键和代码摘要；重试沿用原键，编辑代码后再次明确提交才创建新键。网络未知状态显示“确认受理结果”，查询/重放后再允许新建请求。按钮禁用仅防误点，真正去重由服务端完成。

截止基于服务端时间校准显示，但最终由服务器裁定。倒计时归零后刷新状态，不把浏览器时间当受理事实。正式意图被拒绝时保留代码，明确展示截止或平台原因，让学生自行选择练习或等待补偿。

## 5. 状态与反馈

| 状态 | 文案及行为 |
| --- | --- |
| 加载 | 使用区域骨架；不阻塞无关内容；避免整页闪白 |
| 空数据 | 说明原因和下一步；无推荐即“暂无符合条件的练习” |
| 字段错误 | 字段下方说明格式/单位，摘要可定位首个错误 |
| QUEUED/JUDGING/RETRY_WAIT | 排队中/评测中/恢复处理中；未知等待时间不虚构倒计时 |
| SE | “平台评测异常”，显示可追踪请求和恢复状态；不归入学生错题 |
| 成绩暂定/重评中 | 明确版本和状态；新旧差异可查看，旧结果只读 |
| 429/503 | 区分个人限制与平台故障；显示可重试时间；代码保留 |
| 模型不可用 | 固定帮助正常展示，提示独立说明失败或额度不足 |
| 409 | 展示版本冲突并重新载入摘要；不自动覆盖用户编辑 |

作业发布、统一重评激活、延期、归档、清理确认需要展示对象、影响人数、版本和理由；只有确有破坏性或业务影响的动作二次确认，普通保存不反复弹窗。

## 6. 可访问性与界面验收

所有按钮、表单和对话框使用语义元素；输入有关联 label；键盘焦点清晰；弹窗管理焦点并支持 Escape；状态更新使用适度 live region，轮询不能重复朗读全部内容。图标有可访问名称，工具提示不能是唯一说明。编辑器支持跳出键盘捕获。

需要验证1366×768、1440×900、390×844视口，三种桌面浏览器及前一稳定版、两类移动浏览器、键盘、减少动态偏好、200%文字缩放。截图回归仅辅助视觉一致性，不能代替业务和可访问性验证。

P0交付设计令牌和登录/工作区/表格基础组件；P1交付真实数据闭环；P2覆盖所有异常/权限/恢复状态；P3完成可用性与跨浏览器验证。禁止用静态假数据截图宣布页面功能完成。
