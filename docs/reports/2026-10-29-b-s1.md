# S1 共享事务与数据库时钟验证

日期：2026-10-29；实施人 B祝祎帆；基线 `37e3a40`（包含 main `ec3fb0b`）加本轮未提交增量。验证结果不冒称来自新commit或远端CI。

## 实现与范围

新增独立服务端依赖锁、PostgreSQL连接工厂、单次使用的UnitOfWork和DatabaseClock；新增真实数据库测试与 `tools/check_server.ps1`，总入口保留A、前端和离线模型检查后追加B检查。CI中B仅引用已有测试数据库环境变量。

SQLAlchemy负责同一Connection上的提交/回滚/释放；应用模块不得自行commit。时钟读取数据库 `clock_timestamp()` 并转换UTC毫秒，调用方必须在取得规定锁后读取。此阶段没有生产HTTP、业务表迁移、A正式Repository切换、评测执行或成绩功能。

## 环境与过程

- Windows Python3.12.13、uv0.13.5、Node24.16.0、pnpm11.21.0；真实数据库为Ubuntu WSL2中的PostgreSQL16.15。
- 专用非超级用户和 `_test` 数据库；测试schema为随机 `b_shared_`，用例清理只操作自身schema。连接值在忽略目录保存，不写入仓库或本报告。
- 最初运行新测试，因 `app.shared` 尚不存在出现2个收集错误；随后实现，先确认Ruff/mypy，再运行真实数据库用例。
- 首次真实库运行有6个连接错误。核验WSL内可访问、Windows本机端口拒绝后保持WSL会话存活，重新检查TCP连通并完整重跑，14项通过。不将环境失败计作通过。
- 旧uv下载依赖发生超时，更新到A指定的0.13.5后按同一锁成功安装；没有删除或放宽测试。
- 第一次完整入口已通过前端和A的114项数据库测试，但A浏览器启动失败：Corepack从仓库根目录选择pnpm11.24.0，前端要求11.21.0。修复check_a_line.ps1，在调用pnpm前进入apps/web，结束后恢复目录；保留锁定版本和所有用例，随后重跑完整入口。原失败日志保留为忽略文件.local/s1-check-all-first.log。
