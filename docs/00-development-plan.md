# 项目开发总纲

版本：0.3 · 状态：已审定开发基线 · 审定日期：2026-10-20

## 1. 目标与范围

Astra是面向课程教学的编程学习平台，完成教师发布作业、学生提交、隔离评测、学习反馈、统一重评和成绩发布。支持学生、任课教师、管理员三类角色；支持C++17和Python 3的标准库、单文件、单执行线程、标准输入输出文本题。

正式交付覆盖[FR-01—FR-29](01-requirements.md)。公开竞赛、排行榜、查重、社区、支付、校园统一认证、教务回写、多文件工程、交互题和自研沙箱不在范围内。

交付包括源代码、依赖锁、数据库迁移、接口契约、测试、部署配置、运行手册、演示数据和对应版本的验收报告。

## 2. 技术架构

| 层次 | 选型 | 主要约束 |
| --- | --- | --- |
| 前端 | React、TypeScript、Vite、React Router、TanStack Query、CodeMirror 6 | 同源API、统一设计令牌、编辑器按需加载 |
| 业务服务 | Python、FastAPI、Pydantic、SQLAlchemy、Alembic | 模块化单体；API与Worker共享领域规则 |
| 数据与任务 | PostgreSQL、事务任务表、Outbox | 数据库为权威账本，受理和任务一次落库 |
| 评测 | Judge0 CE适配端口、专用Linux VM | 业务宿主不执行学生程序；先验证隔离及资源限制 |
| 提示 | 服务端模型网关、DeepSeek官方服务 | 授权白名单、次数/费用预算、固定帮助降级 |
| 工程 | pnpm、uv、Docker Compose、pytest、Vitest、Playwright、k6 | 锁定版本和镜像摘要；真实数据库集成测试 |

代码按[架构设计](02-architecture.md)组织；接口和数据分别以[接口契约](03-api-contract.md)、[数据设计](04-data-design.md)为准。具体依赖与执行环境在P0锁定。

## 3. 双人责任

| 路线 | 实施范围 | 交叉责任 |
| --- | --- | --- |
| A：覃锐谦 | 身份与课程；题目/作业管理、编辑器、固定帮助、模型提示、错题及推荐的服务与页面 | 公共UI规范与组件、教学流程；审查B的接口和完整用户流程 |
| B：祝祎帆 | 提交/评测、结果与历史、成绩/重评、导出/通知及管理操作的服务与页面 | 公共服务、CI、迁移协调和简洁部署脚本；审查A的权限与事务 |

A/B对应上述固定成员，GitHub账号和提交邮箱在P0登记。每项任务由一人实施、另一人评审。模块所有权、跨模块协作和交付任务以[阶段计划](06-roadmap.md)为准。

## 4. 阶段交付

| 阶段 | 结果 | 核心出口 |
| --- | --- | --- |
| P0 工程基础 | 契约、最小纵向工程、UI基础、隔离执行验证 | 两人独立重建；页面→API→数据库贯通；两语言安全执行；基础CI实际运行 |
| P1 可靠教学闭环 | 账号→课程→题目预检→作业→提交→结果→成绩 | 权限、截止、幂等、租约清理、有限恢复与计分可验证 |
| P2 完整业务规则 | 全量重评、公平补偿、模型提示、版本化帮助、归档 | 并发一致性、故障补偿、真实提示质量与任务恢复验证通过 |
| P3 交付验收 | 导出、错题、通知、推荐、容量与交互优化 | 全需求验收、独立部署和回滚；无阻断缺陷 |

按课程规模交付单一可重建环境、必要管理页及备份/恢复脚本，不建设高可用、值班或复杂运维平台。安全隔离、任务恢复、成绩一致性和真实备份验收保留。

需求优先级决定开发顺序，不能将缺项记为完成。工期、任务依赖、前置资源和验收责任统一维护在[阶段计划](06-roadmap.md)。

## 5. 开发和变更控制

全员在Codex使用Superpowers与Build Web Apps，按[开发工作流](../CONTRIBUTING.md)执行设计、计划、开发、调试、审查、验证和分支集成。业务规则以需求规格为准；接口先定、再并行开发；历史版本不可覆盖；推送前完整检查，合并前核对双方最新远端提交及未推送依赖。

范围、权限、计分、截止、技术栈或验收阈值变更须说明影响、迁移与验证，双方评审并同步相关规范。原始提交仅在archive保留，当前开发文件通过Git版本管理，不复制多套最终版。
